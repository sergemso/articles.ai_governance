## Abstract

The discourse on artificial intelligence is dominated by two claims that are rarely separated: that AI development is hitting technical limits, and that leading laboratories are shaping regulation to protect their market position. This essay argues that neither claim, stated in that form, is analytically useful. The relevant change is not a ceiling on capability but a shift in the economic gradient of deployment: the cost of fixed capability is collapsing, production traffic is migrating to commoditized open-weight models, and the premium for frontier capability is decaying. Drawing on Carlota Perez's theory of technological revolutions, the essay interprets this shift as a transition from product competition toward infrastructure competition. It then examines the institutional response: the Anthropic/METR embedded-evaluator arrangement and the draft bill that would generalize it. The essay does not infer motive; it evaluates design. An eight-dimension framework distinguishes observed design features from the mechanisms that may produce exclusionary effects and from the evidence that would demonstrate such effects. The framework is then validated against three further cases: the EU AI Act's conformity-assessment regime, China's algorithm registration regime, and the UK AI Safety Institute.

## Build Instructions

### Prerequisites

- **LaTeX distribution** with `pdflatex` and `bibtex` (TeX Live, MiKTeX, or MacTeX) - for PDF
- **Pandoc 3.x** - for DOCX (install from <https://pandoc.org/installing.html>)

### Build the PDF (canonical output)

```bash
make pdf        # runs pdflatex → bibtex → pdflatex → pdflatex
```

Or manually:
```bash
cd paper/
pdflatex article.tex
bibtex article
pdflatex article.tex
pdflatex article.tex   # second pass resolves cross-references
```

Output: `paper/article.pdf`

### Build the DOCX (derived artifact)

```bash
make docx
```

This runs:
```bash
pandoc --output=manuscript.docx --from=latex --to=docx \
       --citeproc --bibliography=paper/refs.bib paper/article.tex
```

Output: `manuscript.docx` (in the repository root)

The DOCX is regenerated by CI on every push that touches `paper/**`. You do not need to commit it manually - the workflow commits it back to `master` automatically.

### Clean

```bash
make clean      # removes LaTeX build artifacts + manuscript.docx
```
